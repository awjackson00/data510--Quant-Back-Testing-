1 Research Question Reminder

This project examines how portfolio optimization can help stakeholders construct portfolios that preserve return potential while reducing drawdowns during periods of financial crisis and market uncertainty. The frozen data scope supports this question by collecting historical daily market data for selected securities, sector portfolios, defensive assets, and benchmark indexes. These data allow us to compare portfolio behavior across growth periods, normal market periods, and crisis regimes using total return, drawdown, volatility, Sharpe ratio, Sortino ratio, and sector-level performance.

  • Primary research question:
    • How can portfolio optimization help stakeholders construct portfolios that preserve return potential while reducing drawdowns during periods of financial crisis and market uncertainty?
  • Sub questions:
    1. Do drawdown-resistant portfolios experience significantly lower gains during growth years compared to regular market indexes?
    2. How does portfolio performance during crisis periods compare to performance during normal market conditions?
    3. How are Sharpe and Sortino ratios affected during periods of uncertainty compared to periods of growth?
    4. How do different asset classes and sectors, such as technology, energy, real estate, consumer staples, and defensive treasury-based assets, behave during periods of market stress?

The data scope is now frozen around the portfolios, benchmarks, and historical market data needed to answer these questions. Future work will focus on analysis, modeling, optimization, and communication rather than adding new data sources.

2.1 Portfolio Construction Inventory

The project currently organizes assets into five main constructed portfolios plus market benchmarks.

  1. Mega-Cap Technology Portfolio
    This portfolio includes large technology and growth-oriented companies from the last 25 years, including Apple, Microsoft, NVIDIA, Google, Amazon, Meta, Broadcom, and Tesla. The purpose of this portfolio is to represent concentrated exposure to high-growth technology firms.

  2. Barbell Portfolio
    This portfolio is based on barbell investment theory. Most of the portfolio is allocated to defensive or risk-free bond exposure, while a small portion is allocated to a volatility-sensitive asset. In the current construction, 95% is allocated to risk-free or treasury-based securities and 5% is allocated to a volatility proxy. This portfolio is designed to test downside protection and market-stress resilience.

  3. Energy Portfolio
    This portfolio includes ExxonMobil, Chevron, ConocoPhillips, EOG Resources, Schlumberger, NextEra Energy, Duke Energy, Constellation Energy, Southern Company, and Dominion Energy. The portfolio provides exposure to oil extraction, oil refinement, energy services, utilities, and electrical infrastructure.

  4. Real Estate Portfolio
    This portfolio tracks real estate exposure using an aggregated commercial real estate ETF from Vanguard. This allows the project to evaluate how real estate behaves during normal markets, inflationary periods, and high-interest-rate environments.

  5. Fast-Moving Consumer Goods Portfolio
    The final portfolio tracks fast-moving consumer goods, or FMCG. This portfolio includes grocery and retail companies such as Walmart, Costco, and Target; branded consumer goods companies such as Procter & Gamble, Unilever, and Kimberly-Clark; and food and beverage companies such as Coca-Cola, PepsiCo, Nestle, and General Mills. This portfolio is intended to represent defensive consumer demand.

  6. Benchmarks
    The project uses market benchmarks to compare portfolio performance. These include regular market indexes and benchmark return series such as the S&P 500, market excess return where applicable, and a risk-free rate proxy. These benchmarks provide reference points for evaluating whether the constructed portfolios outperform, underperform, or trade return potential for drawdown resistance.

3 Schema and Organization

The project is organized around portfolio dictionaries and date-indexed financial dataframes. The portfolio construction dictionaries define each portfolio as a set of ticker and weight pairs. These dictionaries are then used to download historical price data, calculate daily returns, and aggregate individual asset returns into portfolio-level return series.

The project does not require a fully normalized 3NF relational database because the analysis is time-series based and can be handled efficiently through pandas dataframes. However, the data still have clear keys, indexes, and transformation paths. The central unit of observation is a daily market observation for a ticker or portfolio.

3.1 Logical Data Structure

The project follows this logical flow:

  1. Portfolio definitions
    Team-created dictionaries define portfolio names, tickers, and weights.

  2. Raw market data
    Historical adjusted prices are downloaded from Yahoo Finance through yfinance.

  3. Asset-level returns
    Adjusted prices are converted into daily percentage returns for each ticker.

  4. Portfolio-level returns
    Individual asset returns are weighted and combined to create daily portfolio return series.

  5. Regime and crisis labels
    Date ranges are assigned to market regimes, including crisis periods, growth periods, and normal market periods.

  6. Analysis-ready metrics
    Portfolio return data are used to calculate cumulative return, maximum drawdown, volatility, Sharpe ratio, Sortino ratio, and crisis-specific performance metrics.

3.2 Keys and Join Paths

Data Object Key / Index Purpose
Price dataframe date, ticker Tracks adjusted prices for each asset over time
Return dataframe date, ticker Tracks daily percentage returns for each asset
Portfolio dictionary portfolio, ticker, weight Defines portfolio construction
Portfolio return dataframe date, portfolio Tracks daily weighted returns for each portfolio
Regime dictionary start_date, end_date, regime_name Labels market conditions by date range
Combined returns dataframe date, portfolio_or_benchmark Holds final portfolio and benchmark return series

The main join path is:

portfolio weights + asset returns -> weighted asset returns -> portfolio-level returns -> crisis/normal regime labels -> performance metrics

This structure allows the team to move from raw daily prices to analysis-ready portfolio comparisons without needing a full relational warehouse.

3.3 Raw vs Analysis-Ready Layers

  • Raw layer: Market prices pulled from Yahoo Finance and the team-created portfolio definitions.
  • Interim layer: Cleaned adjusted prices and daily return calculations.
  • Analysis-ready layer: Portfolio-level returns, benchmark returns, crisis-period labels, and performance metric tables.

The current work is stored primarily in the EDA Capstone.ipynb notebook inside the notebooks/ folder. The portfolioConstruction(1).ipynb notebook was used for initial portfolio construction work, and SharpeRatioSheet.ipynb supports the risk-adjusted performance calculations, including Sharpe and Sortino ratio analysis. As the project matures, derived tables can also be exported to data/raw/, data/interim/, and data/processed/ folders for clearer DS3-style organization.

4.1 Ingestion Pipeline

The ingestion pipeline follows this order:

  1. Define portfolio tickers and weights.
  2. Define benchmark tickers and market regime windows.
  3. Pull adjusted historical price data using yfinance.
  4. Convert adjusted prices into daily returns.
  5. Rebalance portfolio weights as assets become available.
  6. Aggregate weighted returns into portfolio-level return series.
  7. Compare portfolio returns against benchmarks and market regimes.
  8. Calculate performance metrics such as cumulative return, volatility, Sharpe ratio, Sortino ratio, and drawdown.

4.2 Failure Handling

Potential ingestion issues include unavailable tickers, assets with short trading histories, missing daily prices, or API interruptions. These issues are handled by checking first available trading dates, missing values, and whether each portfolio has enough observations for comparison. If a ticker is unavailable or has insufficient history, the team will either use a reasonable ETF proxy, restrict the analysis window, or document the limitation.

The project does not require scheduled scraping. Since the analysis is historical and the M2 data scope is frozen, the ingestion process is treated as a reproducible one-shot pull rather than a recurring production pipeline.

5 Data Quality and Profiling

The main data quality concerns are missingness, asset availability, outliers, benchmark comparability, rebalancing assumptions, and volatility proxy limitations.

5.1 Missingness and Asset Availability

The frozen M2 data snapshot is analyzed through 2026-06-28. The price dataframe contains daily trading observations for the selected portfolio assets and benchmarks. The asset return dataframe has the same asset coverage, but the first trading day is not usable for return analysis because daily returns require a prior price observation. As a result, the combined portfolio and benchmark return dataframe begins one trading day after the first available price date.

Missingness within portfolios is handled by rebalancing the portfolio as asset data become available. This is important because some companies went public after January 2000 and therefore do not have full historical coverage. For example, the Mega-Cap Technology Portfolio includes companies with different IPO dates, so equal weighting is maintained among available assets until additional assets enter the portfolio.

This approach reflects a realistic rebalancing practice, but it also means that portfolio composition changes over time. The analysis will document this limitation when comparing early periods to later periods.

5.2 Duplicates

Duplicates are not expected to be a major issue because each equity, ETF, or index is tracked by a unique ticker and indexed by date. Each ticker-date combination should appear once in the raw price data. If duplicate ticker-date rows are found, they will be removed before return calculations.

5.3 Outliers

Outliers are intentionally preserved because extreme market movements are central to this project. The goal is to examine how portfolios behave during stress events, so large negative or positive returns should not be automatically smoothed out. However, extreme values will be reviewed to distinguish true market events from possible data errors.

5.4 Portfolio Weight Checks

Each portfolio must maintain valid allocation weights. Equal-weighted portfolios should sum to 1 across available assets, and the barbell portfolio should preserve its 95/5 allocation logic. Weight checks are necessary because incorrect weights would distort portfolio return, volatility, Sharpe ratio, Sortino ratio, and drawdown results.

5.5 Market Coverage Caveats

The five constructed portfolios primarily track different sides of the market, including equities, defensive securities, and sector-specific exposure. Because many assets still respond to broad market conditions, the team expects some covariance between portfolios. Part of the analysis will examine whether diversification benefits remain meaningful during crisis periods or whether correlations increase during market stress.

5.6 Volatility Proxy Caveat

Finding an acceptable proxy for market volatility presented an initial challenge. The variable used in the current version is the Volatility Index, or VIX. The VIX was created to track implied volatility from options markets and became tradable through volatility derivatives in the 2000s. Since the current portfolio tracks the price of ^VIX, the barbell portfolio has limited history before 2004. In addition, ^VIX itself is an index rather than a directly investable asset, so the final analysis will either treat it as a stress proxy or clearly document it as a limitation.

6 Reproducibility

This project is reproducible because the portfolio definitions, tickers, date ranges, and data pull process are contained in the project notebooks. A peer could rerun the notebooks to reconstruct the same market data pull, daily return calculations, portfolio return series, risk-adjusted metrics, and visualizations.

6.2 Rebuild Instructions

To rebuild the analysis-ready data:

  1. Clone the project repository.
  2. Install the required Python packages.
  3. Open the EDA Capstone notebook in the notebooks/ folder.
  4. Restart the kernel and run the notebook from top to bottom.
  5. Confirm that the price data, return data, portfolio return data, and visualizations are regenerated.
  6. Run SharpeRatioSheet.ipynb if updated Sharpe and Sortino outputs are needed.

Example environment setup:

pip install pandas numpy yfinance matplotlib

To preserve reproducibility for this milestone, the project freezes the analysis window at 2026-06-28 and documents the pull date, asset list, benchmark list, and portfolio construction logic used for the M2 data summary.

7 Ethics and Access Controls

All data used in the current project are public financial market data. No personally identifiable information, private investor records, account-level data, or restricted financial information are collected.

The primary ethical risk is that the results could be misinterpreted as investment advice. To address this, the project will clearly state that all analysis is historical and educational. The project does not recommend that stakeholders buy, sell, or hold any specific asset.

A second ethical limitation is that backtesting can create false confidence. Historical performance does not guarantee future results. The project will avoid presenting any portfolio as objectively “best” for future investing and will instead frame results as evidence about how these portfolios behaved under selected historical conditions.

A third limitation is survivorship bias. The selected assets are securities that are currently known and available, which may exclude firms or funds that failed, merged, or disappeared. This limitation will be documented in the analysis and final write-up.
